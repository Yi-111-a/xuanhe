3. **结局判定口径不一**：简报目标写「中兴诸结局还须……国库 ≥ 210、佞幸 < 40」，唇齿相依的条件却是「国库 ≥ 200、佞幸 < 45」。建议简报同时列出各结局的门槛，或统一口径。
4. **复盘归因不准**：复盘写「宣和三年冬：东宫讲读：佞幸用事 < 45（结局条件由此成立）」。佞幸跌破 45 是多季累积的结果，归于某一条奏疏很随意；而决定性的「以粮帛助辽」（T1 辽使来聘 grain）反而没有列入要事。
5. **危险的默认选项**：T15「密诏招天祚」默认 `invite`（史上即金人南侵口实），T9「艮岳成」默认 `feast`。玩家漏看待决事件就自动走最坏分支。可以接受，但建议在 end_turn 前若有待决事件给出显式提醒（目前只在简报里列出）。
6. **朝中效果被驿程拖延**：T0「召还李纲」选项里，「佞幸 −3、君威 +1（开言路）」随李纲的驿程延到下季。授官延迟合理，但朝中风气的变化不该等人到京。
7. **有司稽迟的随机延期粒度**：一条奏疏选项内部可能拆成一半即行、一半延期（T17「西夏附金 gifts」：国库 −40 和关系 +20 延期；T19「淮南 relief」整条延期）。规则本身可以理解，但「本季延期概率约 4%」的提示只在回执里出现，事前看不到。
8. **金人轻宋只升不降的手段太少**：除「金主之丧 gifts」外，几乎所有选项（包括谢绝金使、助辽）都会让「金人轻宋↑」，玩家缺少主动压低它的手段；全局主要靠武备的负贡献去抵消。

## 四、改进建议

1. **奏疏文本条件化**：对涉及「燕山 / 伐燕 / 南讨 / 夹山 / 城池多圮 / 左藏无几」的句子加状态判断（是否已伐燕、辽祚、地区防务、国库比例），或准备多套文案。
2. **谏言人过滤**：致仕、流放、已死者不再出现在奏疏谏言里；或标注「（致仕在家，上书言）」。
3. **人设卡动态化**：开场白和头衔随官职 / 状态更新（宗泽、吴乞买、马扩）；记忆去重并修正日期；易帅、恩宠变化写入记忆。
4. **廷议立场**：派系立场应以人物自身的已知主张为先（同一奏疏中本人的谏言优先于派系推定）；自由议题在缺少「上意」时给出「未置可否」，不要默认附议；书面议状要有实质理由，并允许挂接待决事件（choice_id）。
5. **对账一致性**：「军报晚到」事件要么记在本季「事件/选择」并让事实前后值相衔接，要么在事实中注明「已计入上季期末」；每一项「事件/选择」都要能在事实列表里找到出处。
6. **风闻区间**：保证区间中心随真值移动，或在简报里注明「区间每季重新抽样，不代表趋势」；危机计「其他（截断等）」要给出具体项。
7. **勘会单列**：把冷却计时移出「工程」，只在奏疏条目下注明「x 季后再议」。
8. **外交关系可见**：简报加一节「诸国关系」（宋—辽 / 金 / 夏 / 高丽），事实里写清变化原因。
9. **财政平衡**：适当提高结局国库门槛（例如按开局比例），或增加中后期的硬性开支事件，让府库目标有存在感。
10. **工具层**：client 模式 audience 记录并回传 question；court_debate 支持 `choice_id`；end_turn 对「全部条款被拒的草案」的处理写进文档；ops `remember` 要么限制，要么说明它对后续事件有无影响；`appoint` 回执中提示才干是否相合。
11. **错误文案**：OP_NOT_PERMITTED 对 `start_project.on_complete` 的提示去掉自相矛盾的「工程竣工效果」一项。
