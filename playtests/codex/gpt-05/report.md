## 问题记录与改进建议

以下区分实际报错、可复现的呈现问题、规则疑问与机制体验；没有把猜测写成已经证明的引擎缺陷。

### 实际工具问题与卡顿

1. **宣和二年夏，本地调用封装报作用域错误。** `functions.exec` 执行 `eval(load("helper")); await x(...)`，返回 `ReferenceError: x is not defined`。这是我在编排工具时的错误，尚未向 draft_edict 发出该次请求，未改变游戏。改为保存函数表达式并以 `const x=eval(load("helper"))` 取得函数，再提交成功。建议：客户端封装显式返回函数，避免依赖 eval 的声明作用域；与游戏错误分别记录。
2. **开局两次合并输出被截断。** 首次工具发现加目录／记忆检索，以及把 briefing、op_reference、policy_cards、audience 合并返回时，`functions.exec` 都出现 `Warning: truncated output`；后一份原始输出为14845 tokens。这会使操作参考与卡片说明不完整。我重新单独取得 policy_cards，并随后保留原始结果、分段展示必要内容。建议：工具参考减少重复通用说明，支持卡片按 card_id 查询；客户端按用途分批返回。
3. **xuanhe MCP 本身没有返回 isError，也未出现 rejected 条款。** 没有遇到存档丢失、网络失败、无法推进或 GAME_OVER 误调用。未发生同一错误连续出现三次的情形，因此没有触发该规则的第三次换路要求。上述本地错误均已纠正并继续完局。

### 数字与时序问题

4. **宣和七年春结算，危机总变化与分项显示无法闭合，优先建议检查。** 调用 `end_turn(session_id=上述存档)` 后，“胡马南牧变化”是 `+0.5～+1`，漂移却是 `-0.3～+0.2`，地狱难度加成为 `0`，没有列事件冲击。官方 export_log 对该季给出的 `items=[]`、`other=0`，同时保留这些显示值。仅从公示分项无法解释总变化。最后一季也出现总变化 `0～+0.5`、漂移 `-0.4～+0.1`、难度 `-0.1～0` 的类似情况。可能漏列固定难度漂移，也可能总量与分项用了不同区间／取整口径；本局不据此推算隐藏真值。建议：所有贡献项使用一致口径，补全固定项和取整残差，使总量可核对。
5. **宣和二年秋与最后一季，待决事件早于对应军报出现。** 二年夏 end_turn 已打开 `choice-lunan_yi-2`；秋季 `choose(..., option_id="amnesty")` 已执行招抚，但秋结算才收到“泸南夷扰边（军报晚到：十月初一日自川峡奏到）”。最后一季对 `choice-lunan_yi-22` 也先招抚，再在终局收到该军报。其他北苑贡茶亦有类似顺序。即时选择结果与后到事实中的地区旧值不同，不宜当作同一时间点对比。建议：待决事件注明“先获急报、详报后至”，并在后报清楚区分原发影响、选择影响与是否已入账。
6. **宣和三年秋结算有跨季隐去的钱款，读起来像账不符。** 该季末国库为1598，事件／选择净额为 `+5`，当时可见的“夏人入市”只有国库 `−10`；下一季才看到高丽回赐 `−15` 与海舶抽解 `+30`，并注明“已计入上季对账”。因此不能判为重复扣款，但当季不能完整复核。建议：保留远地叙事延迟，同时在当季对账列匿名“未到详报支出／收入”的金额与关联号，下季自动关联销账。
7. **宣和七年夏，回执未提示效果已到下限。** `draft_edict(adopted=[{memorial_id:"t_chendong_liang",option_id:"punish"},...])` 在佞幸已为0时仍列 `佞幸用事 −6`；终局前后的真实公开值仍为0。此前罢童贯也有下限截断。应理解为上限／下限机制，但预览的名义收益容易误导。建议：回执同时列名义变化、实际可生效变化，以及“已至下限”。
8. **终局风闻区间跨过胜负线，不能单靠区间判断达标。** 最终 briefing 显示胡马南牧约39–46，outcome 却确认 `<45`。这不是数值矛盾：区间不是隐藏真值，判定由引擎作出。建议：终局保留雾战，同时在该指标旁直接标“本项已达成”，减少玩家误把区间上界当真值的困惑。
