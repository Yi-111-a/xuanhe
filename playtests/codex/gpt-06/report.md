## 工具报错、卡住与恢复记录

**游戏 MCP 本局没有 `isError=true`、条款 `rejected` 或阻塞性报错。** 因此未触发「同一错误连续三次换办法」条件。没有未确认草案卡住结算、没有召对不在场或廷议超额问题。有司稽迟和远地令达均属正常回执，例如三年夏赈京东、五年春李纲三事及和籴、五年冬和买；都确认后正常结算生效，未误报为失败。

报告阶段发生过一个本地工具错误，与游戏状态无关：

- 用 Windows PowerShell `Get-Content -Raw | ConvertFrom-Json` 读取UTF-8的 `session-log-final.json`，没有指定编码，中文变成乱码，`ConvertFrom-Json` 报「传入的对象无效，应为 ':' 或 '}'」；命令退出码1。
- 随即换用 Python `read_text(encoding='utf-8')` 解析成功，确认原JSON文件有效；没有对同一错误盲目连试。补指定UTF8后PowerShell可解析，但其数组管道分组未正确展平成逐条记录，最终统计采用Python和引擎 `export_log` 的交叉核对。
- 未发生游戏卡死、网络失败或存档丢失。终局新事件无法处理属上文引擎流程问题，而非本地解析问题。

## 改进优先级

- **优先修终局流程**：不要在封局后留下可选事件和未来期限；统一终局简报、结算和存档中的待决状态。
- **补决策因果反馈**：按实际外交、御笔改革、主帅、已建设施生成文本；解释大饥、河决与此前准备的关系。
- **公开时间边界与资金排期**：修堤保护起止季、远地军报原季、工程成本及最后一季风险应易于核对。
- **减少固定循环取收益**：周期奏疏体现维护、灾情和边际收益，任官提供适任候选，工具输出提供摘要模式。
